## M1 具体实施顺序

1. 确认首批合法文档来源、版本、许可与存储规则；固定约 20–30 份样例和约 50 道人工核对题。
2. 设计并迁移知识库、文档版本、切分片段、向量和处理任务的最小数据模型。
3. 建立 Markdown/PDF 上传、文件限制与隔离存储、解析与结构化切分、失败状态和重试。
4. 接入可配置 Embedding 服务，记录模型与索引版本，执行 pgvector Dense Top-K 检索。
5. 提供带真实文档位置的引用回答；证据不足时明确拒答，不伪造来源。
6. 完成前端上传、状态、提问与引用跳转，并在真实数据库和样例文档上跑通端到端验收。

当前第 2–6 项的基础链路已落地；28 份语料已全部纳入可重建清单。下一步先由人工核对 `datasets/m1-review-queue.csv` 的 50 道题、可回答性和原文范围，处理 6 道 Top-5 未命中题；再补充 Spring Boot 等格式适配或可追溯来源，锁定语料与题集版本，运行正式检索与拒答基线，并逐条审核生成答案的证据忠实度。当前候选集的 42/48 命中只用于开发检查。

引用卡片的原文高亮已实现并通过接口、类型检查和构建验证；浏览器点击验收待补。正式基线仍以人工审核题集为前提。
